# Adversarial review: NATIVE-DSP-PLAN.md

Reviewer stance: try to falsify. Everything below was checked against
`docs/reviews/FACTS-2026-11-13.md`, the repo at `1907c88`, and the live registry
on this host on 2026-11-13. The repo was read only; nothing was written except
this file. No build was run.

## Verdict

The direction is right and the APO is the correct mechanism, but the plan is not
executable as written. Three things break it. First, the plan's stated
registration mechanism is incomplete: writing a CLSID into `FxProperties` does
nothing unless that CLSID also has a COM `InProcServer32` entry, and `beanxctl`'s
declared scope never mentions COM registration, so T0.1 as specified fails with no
diagnostic. Second, the plan's central factual claim about this machine is false:
it says every render endpoint carries an SFX CLSID at `{d04e05a6-...},5`, but only
23 of 30 do and **none of the four ACTIVE endpoints does**, including the Razer
headset the plan picks as its first write. Third, the reversibility proof (T0.2)
is tautological: the backup format records no value types and no `FxProperties`
subkeys, so its `diff` is empty whether or not the registry was actually restored.
On top of that the plan has two privilege models that contradict each other
(register on every launch, versus an elevated install step), an installer task that
cannot run on this box, an unsigned-APO claim that is an inference rather than a
measurement, and a five day schedule holding 20 tasks across a new DSP crate, a
realtime COM layer, a device watcher, a full UI cutover and an installer, with zero
budget for the project's first ever build. Wave 0 as written also violates the
plan's own realtime rule. Verdict: revise before wave 0, do not start.

## What the plan must change

**Section 2, "The mechanism that replaces it"**
- Add the missing registration step as first class content: `HKCR\CLSID\{beanxapo-clsid}\InProcServer32` pointing at the installed DLL, `ThreadingModel=Both`, plus the exported `DllGetClassObject` / `DllCanUnloadNow` (and `DllRegisterServer` if the installer is to use it). State that this is a per machine, elevated write, and that without it the endpoint falls back silently. (P0-1)
- Delete "every render endpoint carries an SFX CLSID at `{d04e05a6-...},5`". Replace with the measured table: 23 of 30 carry it, 0 of the 4 active endpoints carry it, and name what those four carry instead (THX components at `,13`/`,14` plus `SWD\DRIVERENUM\THXAPOCOMPONENT_...` at `,100` on the Razer). (P0-2)
- Retarget the blast radius control. The Razer headset is the worst first choice on this box: it has no `,5`, its effects are driver owned, and Razer's own software rewrites them. Use `{269fb022-...}` (moniteerrrrsss, active, real, no `,5`, `Disable_SysFx` absent) or accept the plan's own offer to do the four active endpoints at once. (P0-2)
- Rewrite "Signing, verified rather than assumed". State the conditional rule from Microsoft's sAPO troubleshooting page (unsigned APOs are not loaded when the graph runs protected content; `DisableProtectedAudioDG=1` is the test-mode escape), keep the EqualizerAPO precedent as prior art rather than proof, and note that the artifact must be kept in `docs/evidence/` with the command output, because it is no longer on disk. (P1-1)
- Replace "after the per-app mixer" with "per stream, before the mix" and state the consequence for instances and meters. (P1-2)
- Add a "ProcessingModes" paragraph: which `{d3993a3f-...}` mode lists get written, which stream categories are covered, and what happens to Communications and Raw streams. (P1-3)
- Add the `PKEY_AudioEndpoint_Disable_SysFx` preflight: read it, refuse to claim success if it is set, and offer to clear it with the user's consent. (P1-4)

**Section 3, "Architecture" and "Scope"**
- Pick one privilege model. Recommended: a small elevated helper (scheduled task or on demand service) that owns all registry writes, service restarts and the device watcher, with the per user app only reading status and writing templates. Delete "on every launch ... applies to every endpoint" or say explicitly that it means "asks the helper". (P0-5)
- Either prove `EnumAudioEndpoints(..., 0xF)` returns 30 by logging the count in `docs/evidence/`, or drop the API claim and say the count comes from `MMDevices\Audio\Render` enumeration. Note that `src/audio.rs:303` already does this enumeration, so `beanxctl` should reuse it. (P1-6)
- Say what a meter block means when several SFX instances write it (sum, max hold, or one designated stream). (P1-2)

**Section 5, Wave 0**
- T0.1: move the marker out of `APOProcess`. Write the counter to shared memory and have a user mode reader dump it, or gate the file write behind a debug flag that is off by default. Add "truncate or timestamp the evidence file before the run" so a stale file cannot pass. Add "keep a copy of whatever the engine logs, because a failed `CoCreateInstance` is silent". (P0-4)
- T0.2: capture value types and subkeys (`reg export` per endpoint, which preserves both), diff those exports rather than a hand formatted dump, and specify that restore deletes values that did not exist before. Then the check can actually fail. (P0-3)
- T0.3: name the capture harness. Nothing in the repo does WASAPI loopback today, and the 90 minute box cannot absorb writing one.

**Section 5, Wave 2**
- T2.3: change "the Microsoft SFX CLSID back on every managed endpoint" to "the exact byte for byte `reg export` of each endpoint's `FxProperties` matches the pre-run export", and note that four of the active endpoints had no Microsoft SFX CLSID to begin with. (P1-5)
- T2.2: make the 100 ms and the 150 ms agree, and state how the slider event and the capture are synchronized. (P1-10)

**Section 5, Wave 3**
- T3.1: add `audio.rs:525`, `main.rs` diagnostics and the `presets.rs` FxSound grammar to the scope, or downgrade the check to "no `FxClient`/`FxEvent` references remain". Drop the README clause from a `src/` grep. (P1-7)

**Section 5, Wave 4**
- T4.1: either install Inno Setup as an explicit prerequisite task with a stated version, or switch to something already present. Rewrite `installer/beanxsound.iss` for a per machine component (`PrivilegesRequired=admin`, DLL to `{pf}`, an `AddReg` for the CLSID, a separate elevated registration step) and keep the per user app install. As written the existing `.iss` is the opposite of T4.1. (P0-6)
- T4.4: add "install the aarch64 std and an arm64 MSVC toolchain" as its own task with a fallback (drop ARM64 from 0.2.0), or delete the task. It cannot pass on this box today. (P1-9)

**Section 5 header and Section 6, schedule**
- Re-date the waves against a real budget: 20 tasks, waves 2, 3 and 4 each a multi day subsystem, and a first build that has never happened here. Add a task 0.0 "cold build succeeds and takes N minutes" before anything else, and state the number. (P1-8)
- Add the first build cost and the missing `Win32_Media_Audio_Apo` feature to the risk table.

**Section 7, Riskiest assumptions**
- Add three rows: the APO is silently dropped if its CLSID has no `InProcServer32`; the APO is silently skipped if `Disable_SysFx` is set; the APO is only instantiated for the processing modes that were declared. All three fail silently, which is the worst failure mode for a plan whose checks are "audio sounds different".

**Section 9, approval ask**
- The ask is larger than described. It includes a per machine COM registration under `HKCR\CLSID`, an elevated helper that stays installed, and (for the Razer target) overwriting a driver owned APO chain. Say that, and say what the exact restore command is.

## Corrections to the facts file itself

The facts file is accurate on the repo and the build host. Three things in it need adjusting.

1. `presets.rs:179` is the doc comment for `apply_args`, not `EqEditor::args`; `Editor::args` is `app.rs:131`.
2. Section 3 lists the four active endpoints but does not record that **none of them carries `{d04e05a6-...},5`**. That single omission is what lets the plan's false "every render endpoint" claim look supported. Add an explicit count line: 23 of 30 have `,5`, 0 of 4 active have it.
3. Section 4's EqualizerAPO artifact is no longer on disk, so the `NotSigned` result is not reproducible. Either re-download and keep the DLL plus the command output in `docs/evidence/`, or mark the claim UNVERIFIED.
4. Section 3 should record registry value types (`REG_SZ` vs `REG_MULTI_SZ` differs between `,5` on HDMI and `,13`/`,14` on the Razer) and the `FxProperties` subkeys, since both matter to the restore design.
